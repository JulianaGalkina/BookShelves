# Инструкции проекта Shelves

## Документы проекта

Перед изменением интерфейса прочитай:

- [PRD.md](./PRD.md) — функции, сценарии, тексты и данные.
- [DESIGN.md](./DESIGN.md) — визуальный стиль, палитра, типографика и правила компонентов.

Также сверяйся с:

- [ARCHITECTURE.md](./ARCHITECTURE.md) — структура приложения, схемы `localStorage` и миграции.
- [PLAN.md](./PLAN.md) — общий план и статус реализации.

Если требования документов расходятся, опиши противоречие и дождись решения пользователя, прежде чем менять соответствующую часть интерфейса.

## Запуск и сборка

В корне репозитория:

- Первый запуск после клонирования: `npm install`.
- Локальное приложение: `npm run dev`.

В `package.json` сейчас нет команды сборки приложения и автоматических тестов. Для ручной проверки используй сценарии в разделе «Проверки результата» файла `PRD.md`.

## Особенности приложения

- Shelves — личный книжный трекер на React и Vite; интерфейс находится в `src/App.jsx` и `src/AuthPage.jsx`, стили — в `src/style.css`.
- Восстановление пароля использует `src/ResetPasswordPage.jsx` и общие функции `src/lib/auth.js`; вход Google и почтовая отправка требуют настройки по `supabase/README.md`.
- Отдельного API-сервера и внешнего книжного API нет; вход, регистрация, книги и полки подключены к Supabase. Старые локальные данные и миграции описаны в `ARCHITECTURE.md`; не удаляй их без переноса пользовательских данных.
- URL проекта и публичный anon/publishable key Supabase задаются в игнорируемом Git файле `.env.local`; секретный `service_role` key нельзя добавлять в клиент или репозиторий.
- Фото обложек выбирает пользователь; они хранятся в приватном Supabase Storage. CSV-экспорт содержит сведения о книгах и полках, но не фотографии.
- Интерфейсные тексты приложения — на русском языке.

## SVG и графика

В текущем проекте нет SVG-файлов или inline-SVG. Перед добавлением графики проверь, можно ли решить задачу существующими средствами CSS и правилами `DESIGN.md`. Новые SVG храни в `src/assets/`; декоративные изображения помечай `aria-hidden="true"`, а функциональные значки снабжай доступным именем через окружающую кнопку или `aria-label`.

## Рабочие ритуалы

- После изменений приложения всегда присылай пользователю ссылку на актуальный сайт с изменениями. Если опубликованного сайта нет, запусти или оставь запущенным сервер разработки и укажи локальный адрес; поясни, что он работает, пока запущен сервер.
- Если меняется поведение, поля, статусы, данные или пользовательский сценарий — обнови соответствующие требования и проверки в `PRD.md`.
- Если меняются ключи `localStorage`, схемы записей, миграции или структура приложения — обнови `ARCHITECTURE.md`.
- Если меняются цвета, типографика, отступы, компоновка или правила компонентов — обнови `DESIGN.md`.
- Если меняются команды запуска, сборки, зависимости или структура проекта — обнови этот `AGENTS.md` и `package-lock.json`, когда меняются зависимости.
- После изменения поведения вручную проверь относящиеся к нему сценарии из `PRD.md`. Не добавляй автоматические тесты без отдельного запроса.
