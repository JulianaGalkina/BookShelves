# План реализации книжного дневника

Основан на согласованном [PRD.md](./PRD.md). План сохранён отдельно; предыдущие документы не перезаписывались.

## Объём первой версии

1. Экран входа и регистрации через Supabase Auth по электронной почте и паролю или через Google; восстановление пароля по ссылке из письма.
2. Один экран общего списка книг с фильтром по статусу.
3. Добавление и редактирование книги: название, автор, статус, впечатление; поля оценки и дат показываются согласно статусу.
4. Статусы: «читаю», «в планах», «прочитано», «отложено». Для читаемой книги автоматически ставится дата начала; при завершении — текущая дата. Даты можно исправлять. Для планируемой книги нет дат и оценки; для отложенной даты нет.
5. Удаление записи и сохранение книг и полок в Supabase Postgres.
6. Адаптивный интерфейс на React + Vite по [DESIGN.md](./DESIGN.md): белый фон, тонкие разделители, цветные обложки и сведения рядом с ними.

## Вне объёма

Социальные функции, рекомендации, внешний каталог книг и другие будущие функции из PRD.

## Завершение

- Запустить локальный сервер разработки.
- Проверить вручную: вход под тестовым аккаунтом, регистрацию и отказ при неверных данных, создание/редактирование по статусам, фильтр и отображение списка, сохранение после перезагрузки.
- Отразить фактический статус и известные ограничения в PRD.

## Статус

Добавлены формы запроса письма и смены пароля, обработка recovery-сессии и Google OAuth. Google пока выключен в облачном проекте; полная проверка входа требует настройки провайдера, а восстановления — доступного почтового адреса и настроенной отправки писем. Инструкция сохранена в `supabase/README.md`.

Основные функции каталога подключены к Supabase Postgres и Storage; вход и регистрация используют Supabase Auth. Структура данных и миграции зафиксированы в ARCHITECTURE.md. Визуальные решения описаны в DESIGN.md. Автоматические тесты не добавлялись по PRD. Требуется ручная проверка с аккаунтом, созданным в Supabase.
