# PRD: Книжный трекер Shelves

**Статус:** React + Vite клиент с Supabase Auth, Postgres и Storage. Этот документ описывает вход, регистрацию, сущности, данные, поведение и проверки. Схема хранения и структура приложения — в [ARCHITECTURE.md](./ARCHITECTURE.md), визуальные правила — в [DESIGN.md](./DESIGN.md), общий план — в [PLAN.md](./PLAN.md).

## Назначение

Shelves — личный книжный трекер. Читатель создаёт аккаунт, ведёт каталог книг, отмечает их статус, сохраняет впечатления и даты чтения, группирует книги по полкам и получает доступ к своим данным после входа с разных устройств.

## Основной сценарий

Пользователь входит или регистрирует аккаунт по адресу электронной почты и паролю. Отдельного логина/имени пользователя нет. После входа он добавляет книги, указывает название и автора, выбирает статус и при желании назначает полку. Он может добавить оценку, впечатление, даты и фотографию обложки. Записи можно изменять и удалять; каталог можно фильтровать по статусу и полке, сортировать и экспортировать в CSV. Кнопка выхода возвращает пользователя на экран входа.

## Вход и регистрация

- На стартовом экране доступны режимы «Войти» и «Регистрация». Обе формы принимают email и пароль.
- При регистрации нужен корректный адрес электронной почты и пароль не короче 8 символов. Адрес приводится к нижнему регистру; email уникален.
- Supabase Auth создаёт аккаунт и сразу открывает пользователю каталог. Подтверждение по email отключено через `Confirm email`.
- Профиль пользователя без отдельного логина создаётся триггером при регистрации. Вход, выход и сессия работают через Supabase Auth.
- В форме входа доступны данные тестового аккаунта `bookishg@shelves.com`; его можно использовать только как общую демо-учётную запись.
- Вход и регистрация также доступны через кнопку «Войти через Google»: пользователь выбирает Google-аккаунт, после успешного входа открывается его каталог. Пароль Google не вводится и не хранится в Shelves. Если провайдер выключен, приложение сообщает об этом и оставляет доступным вход по почте.
- Действие «Забыли пароль?» открывает форму с email. После запроса показывается нейтральное сообщение без раскрытия существования аккаунта. Письмо ведёт на `/reset-password`, где пользователь вводит новый пароль от 8 символов и повторяет его. Только после успешного сохранения показывается «Пароль изменён» и действие «Открыть каталог».
- Переход по ссылке восстановления имеет приоритет над открытием каталога, в том числе при действующей сессии. Недействительная или просроченная ссылка предлагает запросить новое письмо. Обновление страницы сохраняет экран смены пароля при действующей сессии восстановления.
- Отправка письма восстановления не требует включать подтверждение почты при регистрации. Ошибки сети и ограничения частоты запросов показываются в форме; во время запроса повторные действия заблокированы.

## Сущности и поля

### Аккаунт

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | UUID пользователя Supabase Auth. |
| `email` | Обязательно | Адрес электронной почты, управляется Supabase Auth. |
| `password` | Обязательно при регистрации по email | Обрабатывается Supabase Auth; приложение не сохраняет пароль в своих таблицах или `localStorage`. При входе через Google пароль в Shelves не требуется. |

Демо-данные для входа показываются на экране. Сам пользователь должен существовать в Supabase Auth; кнопка демо-входа обращается к Supabase Auth.

### Книга

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | Уникальный идентификатор; создаётся приложением при добавлении книги. |
| `title` | Обязательно | Название после удаления пробелов в начале и конце. |
| `author` | Обязательно | Автор после удаления пробелов в начале и конце. |
| `status` | Обязательно | `reading`, `planned`, `read` или `paused`; для новой книги по умолчанию `reading`. |
| `shelfId` | Необязательно | Идентификатор полки; пустое значение означает, что книга не назначена. |
| `rating` | Необязательно | Оценка от 1 до 5 для статусов `reading`, `read` и `paused`; для `planned` очищается. |
| `impression` | Необязательно | Личное впечатление о книге. |
| `startedAt` | Необязательно | Дата начала для `reading` и `read`; для остальных статусов не сохраняется. |
| `finishedAt` | По статусу | Для `read` автоматически устанавливается текущая дата, если пользователь не указал другую; для остальных статусов не сохраняется. |
| `addedAt` | Обязательно для новых книг | Время добавления в формате ISO; при редактировании сохраняется. |
| `coverImage` | Необязательно | Выбранная фотография обложки как JPEG data URL. Если фото нет, цвет обложки вычисляется по `id`. |

### Полка

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | Уникальный идентификатор, создаётся приложением. |
| `name` | Обязательно | Название после удаления пробелов в начале и конце; названия не должны повторяться без учёта регистра. |

## Связи между сущностями

- Поле `Book.shelfId` ссылается на `Shelf.id`.
- Книга может быть связана с нулём или одной полкой. Полка может содержать любое количество книг, в том числе ни одной.
- Список книг полки отдельно не хранится: он определяется по совпадению `Book.shelfId` и `Shelf.id`.
- Каждая книга хранится в области данных текущего аккаунта. Книги и полки разных зарегистрированных аккаунтов используют разные ключи `localStorage`.

## Создание, изменение и удаление

- При входе или регистрации проверяются обязательные поля, формат адреса электронной почты и длина пароля при регистрации; после успешной проверки локальная сессия сохраняется в браузере.
- При добавлении книги приложение требует название и автора, создаёт `id` и `addedAt`. При редактировании сохраняются прежние `id`, `addedAt` и фотография обложки.
- Новые книги получают следующий цвет после последней добавленной книги во всём каталоге: индиго → коралловый → розовый → жёлтый → бирюзовый, затем цикл повторяется. Первый цвет пустого каталога — индиго. Цвет сохраняется при редактировании, фильтрации, сортировке и перезагрузке; цвета старых записей не меняются.
- Для статуса «прочитано» подставляется дата завершения, если пользователь не указал другую. У «в планах» и «отложено» даты чтения очищаются; у «в планах» также очищается оценка.
- При создании или изменении полки требуется уникальное название. Выбранные книги переходят на неё; снятые с редактируемой полки становятся без полки.
- При удалении книги удаляется только её запись; счётчик полки пересчитывается. При удалении полки после подтверждения книга остаётся в каталоге с пустым `shelfId`.
- При выходе удаляется только активная сессия; локальные аккаунты, книги и полки остаются в этом браузере.

## Хранение и экспорт

Профили, книги и полки хранятся в Supabase Postgres; фотографии — в приватном Storage bucket `book-covers`. Доступ к строкам ограничен политиками RLS по `auth.uid()`. Сессия управляется Supabase Auth. Фильтр и сортировка остаются состоянием страницы. CSV содержит сведения о книгах и название полки, но не фотографии обложек.

Старые данные `localStorage` остаются резервной копией и автоматически не переносятся. Их перенос требует отдельной миграции.

## Проверки результата

1. Войти под созданной в Supabase Auth тестовой учётной записью; убедиться, что после перезагрузки сохраняется сессия.
2. Выйти и войти снова; убедиться, что данные остаются в Supabase.
3. Зарегистрировать новый аккаунт с корректным адресом и паролем от 8 символов. Каталог должен открыться сразу, без письма или кода. Проверить отказ при неверном формате почты, коротком пароле и повторном email.
4. Создать книгу с названием и автором; проверить отказ, если одно из обязательных полей пустое.
5. Проверить четыре статуса, оценки и даты, автоматическую дату завершения для «прочитано».
6. Создать полку, назначить ей несколько книг, переименовать и удалить полку; проверить связи, счётчики и сохранение после перезагрузки.
7. Создать два аккаунта и убедиться, что книги, полки и обложки одного пользователя недоступны другому.
8. Экспортировать CSV и проверить название полки и отсутствие изображения.
9. При наличии прежних данных тестового аккаунта проверить миграцию `folderId` в `shelfId` и прежнего ключа полок.
10. Последовательно добавить шесть книг: первые пять обложек должны иметь разные цвета палитры, шестая повторяет первую. Проверить сохранение цветов после перезагрузки, редактирования и смены фильтра или сортировки. В непустом каталоге новая книга продолжает цикл после последней добавленной книги.

11. Открыть «Забыли пароль?»: проверить пустой и неверный email, возврат ко входу. Запросить письмо на собственный тестовый адрес, перейти по ссылке, проверить короткий пароль и несовпадение, сохранить новый пароль. Выйти: старый пароль не подходит, новый открывает прежний каталог.
12. Проверить `/reset-password` без сессии, просроченную/повторно использованную ссылку и ошибку сети. Должна быть возможность запросить новое письмо. По действующей ссылке при уже открытом аккаунте и после перезагрузки показывается форма нового пароля.
13. После настройки Google проверить первый и повторный вход, выход и перезагрузку, отмену согласия, появление профиля и изоляцию книг. Проверить поведение существующего email-аккаунта с тем же адресом без ручного объединения строк. При выключенном Google вместо перехода на страницу ошибки показывается сообщение в форме.

Проверять состояние аккаунта можно в Supabase **Authentication → Users**, записи профиля — в `public.profiles`, книги и полки — в соответствующих таблицах. Не публиковать `service_role` ключ и не хранить пароли приложения.

## Технические ограничения

- Одностраничное приложение на React + Vite; отдельного API-сервера нет, данные обслуживает Supabase.
- Перед публичным запуском настроить защиту от злоупотребления демо-учётной записью.
- Пользователь вносит названия книг вручную; внешнего книжного каталога нет.
- Автоматические тесты не настроены; проверки выполняются вручную по этому документу.
