# PRD: Книжный трекер Shelves

**Статус:** локальный прототип на React + Vite. Этот документ описывает вход, регистрацию, сущности, данные, поведение и проверки. Схема хранения и структура приложения — в [ARCHITECTURE.md](./ARCHITECTURE.md), визуальные правила — в [DESIGN.md](./DESIGN.md), общий план — в [PLAN.md](./PLAN.md).

## Назначение

Shelves — личный книжный трекер. Читатель ведёт каталог книг, отмечает их статус, сохраняет впечатления и даты чтения, группирует книги по полкам и может войти в свой локальный профиль.

## Основной сценарий

Пользователь входит по адресу электронной почты и паролю либо создаёт локальный аккаунт. После входа он добавляет книги, указывает название и автора, выбирает статус и при желании назначает полку. Он может добавить оценку, впечатление, даты и фотографию обложки. Записи можно изменять и удалять; каталог можно фильтровать по статусу и полке, сортировать и экспортировать в CSV. Кнопка выхода возвращает пользователя на экран входа.

## Вход и регистрация

- На стартовом экране доступны режимы «Войти» и «Регистрация», поля электронной почты и пароля.
- При регистрации нужны корректный адрес электронной почты и пароль не короче 8 символов. Адрес приводится к нижнему регистру; повторная регистрация одного адреса запрещена.
- При входе проверяются адрес и пароль. После успешного входа сессия запоминается в текущем браузере; выход очищает сессию.
- В форме входа показаны данные тестового аккаунта: `bookishg@shelves.com` / `BookishGirrrl`. Можно нажать кнопку входа под этим аккаунтом.
- Это только локальный прототип: учётные записи и пароли сохраняются в `localStorage` без серверной проверки и не обеспечивают безопасность. Не использовать реальные пароли и не считать такой вход production-авторизацией.

## Сущности и поля

### Аккаунт

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | Уникальный идентификатор; создаётся приложением при регистрации. |
| `email` | Обязательно | Нормализованный адрес электронной почты; уникальный без учёта регистра. |
| `password` | Обязательно | Пароль длиной от 8 символов; хранится локально только для демонстрации входа. |

Тестовый аккаунт встроен в приложение и показывается на экране входа; он не создаётся через форму регистрации.

### Книга

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | Уникальный идентификатор; создаётся приложением при добавлении книги. |
| `title` | Обязательно | Название после удаления пробелов в начале и конце. |
| `author` | Обязательно | Автор после удаления пробелов в начале и конце. |
| `status` | Обязательно | `reading`, `planned`, `read` или `paused`; для новой книги по умолчанию `reading`. |
| `shelfId` | Необязательно | Идентификатор полки; пустое значение означает, что книга не назначена. |
| `rating` | Необязательно | Оценка от 1 до 5 для статусов `reading`, `read` и `paused`; для `planned` очищается. |
| `impression` | Необязательно | Личное впечатление о книге. |
| `startedAt` | Необязательно | Дата начала для `reading` и `read`; для остальных статусов не сохраняется. |
| `finishedAt` | По статусу | Для `read` автоматически устанавливается текущая дата, если пользователь не указал другую; для остальных статусов не сохраняется. |
| `addedAt` | Обязательно для новых книг | Время добавления в формате ISO; при редактировании сохраняется. |
| `coverImage` | Необязательно | Выбранная фотография обложки как JPEG data URL. Если фото нет, цвет обложки вычисляется по `id`. |

### Полка

| Поле | Обязательность | Значение и правила |
| --- | --- | --- |
| `id` | Обязательно | Уникальный идентификатор, создаётся приложением. |
| `name` | Обязательно | Название после удаления пробелов в начале и конце; названия не должны повторяться без учёта регистра. |

## Связи между сущностями

- Поле `Book.shelfId` ссылается на `Shelf.id`.
- Книга может быть связана с нулём или одной полкой. Полка может содержать любое количество книг, в том числе ни одной.
- Список книг полки отдельно не хранится: он определяется по совпадению `Book.shelfId` и `Shelf.id`.
- Каждая книга хранится в области данных текущего аккаунта. Книги и полки разных зарегистрированных аккаунтов используют разные ключи `localStorage`.

## Создание, изменение и удаление

- При входе или регистрации проверяются обязательные поля, формат адреса электронной почты и длина пароля при регистрации; после успешной проверки локальная сессия сохраняется в браузере.
- При добавлении книги приложение требует название и автора, создаёт `id` и `addedAt`. При редактировании сохраняются прежние `id`, `addedAt` и фотография обложки.
- Для статуса «прочитано» подставляется дата завершения, если пользователь не указал другую. У «в планах» и «отложено» даты чтения очищаются; у «в планах» также очищается оценка.
- При создании или изменении полки требуется уникальное название. Выбранные книги переходят на неё; снятые с редактируемой полки становятся без полки.
- При удалении книги удаляется только её запись; счётчик полки пересчитывается. При удалении полки после подтверждения книга остаётся в каталоге с пустым `shelfId`.
- При выходе удаляется только активная сессия; локальные аккаунты, книги и полки остаются в этом браузере.

## Хранение и экспорт

Данные хранятся локально в `localStorage`; серверной части и синхронизации нет. Полная схема ключей, форматы записей и правила миграции зафиксированы в [ARCHITECTURE.md](./ARCHITECTURE.md).

- Зарегистрированные аккаунты: `shelves-auth-users-v1`.
- Активная сессия: `shelves-auth-session-v1`.
- Демо-аккаунт сохраняет прежние данные книг и полок в `book-diary-v1` и `book-diary-shelves-v1`.
- Данные каждого зарегистрированного пользователя хранятся отдельно в ключах `book-diary-<id>-books-v1` и `book-diary-<id>-shelves-v1`.
- При входе под тестовым аккаунтом прежний ключ `book-diary-folders-v1` переносится в `book-diary-shelves-v1`, а старое поле `folderId` преобразуется в `shelfId`. Идентификаторы сохраняются, старый ключ остаётся резервной копией.
- CSV содержит сведения о книгах и название полки, но не фотографии обложек.

Очистка данных браузера удалит локальные аккаунты и записи. Данные нельзя получить на другом устройстве. Пароли в локальном прототипе не защищены; перед добавлением серверной авторизации способ хранения должен быть заменён.

## Проверки результата

1. Войти под тестовым аккаунтом `bookishg@shelves.com` / `BookishGirrrl`; убедиться, что после перезагрузки сохраняется сессия.
2. Выйти и войти снова; убедиться, что выход не удалил книги и полки.
3. Зарегистрировать новый аккаунт с корректным адресом и паролем от 8 символов; проверить отказ при неверном формате почты, коротком пароле и повторном адресе, затем войти под созданным аккаунтом.
4. Создать книгу с названием и автором; проверить отказ, если одно из обязательных полей пустое.
5. Проверить четыре статуса, оценки и даты, автоматическую дату завершения для «прочитано».
6. Создать полку, назначить ей несколько книг, переименовать и удалить полку; проверить связи, счётчики и сохранение после перезагрузки.
7. Убедиться, что книги тестового аккаунта и нового аккаунта разделены.
8. Экспортировать CSV и проверить название полки и отсутствие изображения.
9. При наличии прежних данных тестового аккаунта проверить миграцию `folderId` в `shelfId` и прежнего ключа полок.

Проверять локальные значения можно в инструментах разработчика браузера: **Application → Local Storage → адрес приложения**. Там видны ключи аккаунтов, сессии, книг и полок.

## Технические ограничения

- Одностраничное приложение на React + Vite; отдельного сервера и базы данных нет.
- Вход и регистрация — демонстрационный локальный прототип, а не безопасная авторизация.
- Пользователь вносит названия книг вручную; внешнего книжного каталога нет.
- Автоматические тесты не настроены; проверки выполняются вручную по этому документу.
